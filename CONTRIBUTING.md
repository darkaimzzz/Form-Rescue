# Contributing to Form Rescue

Thanks for helping. Form Rescue handles people's unfinished writing, so privacy rules come first and are non-negotiable.

## Setup

- Node.js 24 LTS (`.nvmrc`) and pnpm 12 (`corepack enable` or `npm i -g pnpm`).
- `pnpm install --frozen-lockfile`
- Browser tests: `npx playwright install chromium`. Optional: installed Microsoft Edge (`E2E_CHANNEL=msedge`) and Firefox (`pnpm test:firefox`).

## Repository map

| Path                     | What lives there                                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/core`          | Pure logic: `classification` (eligibility, value screening), `schemas` (messages, stored records, limits), `identity` (keyed fingerprints), `matching`, `retention`. No browser globals.                   |
| `packages/storage`       | IndexedDB repository: atomic commits, revisions, epochs, limits, migrations.                                                                                                                               |
| `packages/design-tokens` | Shared CSS custom properties.                                                                                                                                                                              |
| `apps/extension`         | `src/background` (authorization, policy, commits, recovery plans), `src/content` (capture/apply in the isolated world), `src/popup`, `src/pages/*`, `src/platform` (browser adapter), `scripts/build.mjs`. |
| `apps/website`           | Astro static site, docs and the in-memory demo.                                                                                                                                                            |
| `tests`                  | `unit`, `integration`, `e2e` (real extension), `accessibility`, `firefox`, `fixtures` (synthetic pages + server).                                                                                          |
| `scripts`                | Manifest generation, packaging, release validation, asset capture.                                                                                                                                         |
| `docs`                   | PRD, architecture, threat model, data model, testing, release, status, ADRs.                                                                                                                               |

## Everyday commands

```sh
pnpm lint && pnpm format:check && pnpm typecheck
pnpm test                 # unit + coverage (≥90% branches for classification/matching/retention/authorization)
pnpm test:integration
pnpm test:e2e:chrome      # builds apps/extension/dist-e2e/chrome and runs Playwright
pnpm test:a11y            # extension + website axe checks (builds first)
pnpm test:performance     # 200-control budget + website weight budget
pnpm build && pnpm package && pnpm release:validate
```

## Non-negotiable privacy rules

1. **Synthetic data only.** No real drafts, URLs, names, credentials, tokens or browser profiles in fixtures, tests, screenshots, recordings, logs or issues.
2. **Metadata before values.** Eligibility is decided without reading `.value`/`.checked`/selections (`tests/unit/content-dom.test.ts` instruments getters to throw).
3. **No network code** in the extension and no analytics anywhere. ESLint forbids `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`; the release validator scans bundles.
4. **Text, never HTML.** Draft values render as text; `dangerouslySetInnerHTML` is lint-forbidden.
5. **No logging of values or classifier inputs.**
6. **Never widen permissions** without an ADR in `docs/adr/`.

## Coding style

TypeScript strict mode, Prettier (`pnpm format`), ESLint. Match the surrounding code: small functions, comments that explain _why_. Keep the content script lightweight plain TypeScript. All user-visible extension strings go in `apps/extension/src/ui/strings.ts`.

## Tests and fixtures

Add a failing test first. Fixtures are generated by `tests/fixtures/generate.mjs` and served by `tests/fixtures/server.mjs` on two origins (`127.0.0.1` and `localhost`, ports 4173/4174). Use `pressSequentially`/keyboard input in E2E tests — Playwright's `fill`/`selectOption` dispatch untrusted events that capture deliberately ignores.

## Adding a field or framework adapter safely

1. Add a minimal synthetic fixture page reproducing the control.
2. Extend `classifyField`/`buildMeta` so the new control is **excluded by default**; prove it with unit tests, including a throwing-getter test.
3. Enable it only with explicit eligibility rules, then add capture, apply (`applyValue`) and verification.
4. Add E2E coverage: capture, refresh, review, restore, conflict, and a framework rerender case.
5. Update `docs/browser-support.md`, website docs and the changelog.

## Accessibility

Target WCAG 2.2 AA. Keyboard access, visible focus, 44×44 targets, text (not colour) for state, reflow at 320 px. Run `pnpm test:a11y`; automated checks are necessary but not sufficient — describe manual checks in the PR.

## Branches, commits and PRs

- Branch from `main`; ordinary descriptive commit messages.
- **DCO sign-off required** on every commit: `git commit -s` (adds `Signed-off-by:`). No CLA.
- PRs use the template: summary, privacy impact, permission changes, tests run with results, accessibility, docs, synthetic screenshots, migration notes, risks.
- Update docs and `CHANGELOG.md` with user-facing changes.

## Conduct and security

Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Report vulnerabilities privately per [SECURITY.md](SECURITY.md), never in public issues.
